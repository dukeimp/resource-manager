# 稀有金属投资咨询平台

一套部署在 **Cloudflare Workers** 上的稀有金属投资资讯与行情平台：静态 SPA 前端 + JSON API + Cloudflare D1（SQLite）。

系统定位为**投资咨询工作台（消息 → 标的 → 决策）+ 数据采集中枢**：登录后默认进入「投资总览」——顶部一排**系统概览统计卡**（消息库总量 / 今日新增 / 重点数 / 收藏数、全库消息面利多利空分布、贵金属与稀有金属涨跌家数与均幅、持仓市值与浮动盈亏、自选与建仓计划数、未来财经事件与价格预警数），左栏是**近 14 天消息量趋势 + 我的关注 + 重点信息**（系统判定的重点消息 Top 8 + 未来 7 天重要财经日程），右栏是**相关消息**。每条消息在入库时就会标注它影响到哪些标的，点消息里的标的标签即可打开该标的的决策面板，完成「看行情 → 翻该标的的消息 → 加自选 / 建仓计划 / 设价格预警 / 记一笔持仓」。除此之外：一侧按关注关键词从东方财富、新浪财经 7×24、华尔街见闻 7×24 多平台抓取财经消息（碳酸锂、工业硅、沪镍、沪锡、稀土、铜、铝、黄金、白银、美联储加息、降息、通胀、美元指数、汇率等），自动分类入频道、去重入库，支持全文检索、频道 / 来源筛选、收藏与删除。侧边栏为 **11 项平铺、无二级菜单**：投资总览（`#desk`）、稀有金属研究（`#desk?tab=rare`）、材料联想、实时行情（`#desk?tab=quote`）、资讯中心（`#news`）、财经日历（`#calendar`）、持仓与计划（`#portfolio`）、数据采集（`#acquire`）、用户管理（`#users`）、通知与集成、系统设置（`#settings`）；贵金属品种当前为**沪金主连 / 沪银主连 2 个**，稀有金属品种可在品种管理中配置。「实时行情」标签为「统计卡 + 可排序报价表 + 银行金价区块」三层结构（2026-11-11 重构，缺失值不再误染红色、轮询不重绘）；金价快照默认 30 分钟采集一次、行情刷新与资讯抓取默认 10 分钟一次，均可在「数据采集」页**按秒配置（最小 5 秒）** —— `wrangler.toml` 的 cron 每分钟唤醒，低于 60 秒的部分由页面访问触发补采，实际以 `fetch_tasks` 表为准。系统配有独立的**数据采集**单页菜单，页内用「消息数据 / 贵金属数据」胶囊标签切换两个数据域，集中管理**数据源启停与连通性、任务启停与按间隔调度、失败保护、分组采集参数与「最近采集」日志**；日志筛选 / 导出、配置导入导出、恢复默认值、每日定点调度等能力由后端 API 提供（见「数据采集 → API」），**当前前端采集页未暴露**。「实时行情」页另设独立的**「银行金价（官网一手数据）」区块**（交通银行 1 个官网一手源 + 独立表 `bank_gold_quotes`），详见「银行金价（官网一手数据）」章节。**本系统只做观察、预警与持仓记账，不接入交易通道、不代下单。**

## 功能

- **投资总览**（登录后默认首页，3 个标签页）：一条主线把「消息 / 行情 / 决策」串起来 ——
  
  - **系统概览统计卡区（2026-11-13 晚新增）**：页面最上方一排 6 张卡片，把本系统各张统计表的**总体信息**汇总到一处 ——「消息库」（总量 / 今日新增 / 重点数 / 收藏数）、「消息面倾向」（全库利多 / 中性 / 利空占比 + 分布条）、「贵金属」、「稀有金属」（各自动涨跌家数与平均涨跌幅 + 涨跌分布条）、「我的账本」（持仓市值 / 浮动盈亏 / 自选数 / 建仓计划数）、「日程与预警」（24 小时内财经事件数 / 未来 14 天事件 / 高重要度 / 价格预警数）。卡片内的数字**与资讯中心同口径**（屏蔽词 + 四类相关性白名单），不会出现「卡片 942 条、列表 285 条」的矛盾；部分数字做成可点胶囊，直接跳到对应页面（重点 → `#news?key=1`、收藏 → `#news?starred=1`、自选 / 计划 → `#portfolio`、预警 → `#calendar`）。卡片下方一行小字标注「消息采集于 / 行情刷新于」的实际时间。
  - **重点信息栏**：页面右栏上方的独立面板 ——「**重点消息**」按综合分排序取 Top 8（带「重点 N 分」徽章、研判方向、影响标的、事件类型，标题可点开原文，标的标签可点进决策面板）+「**未来 7 天重要日程**」（财经日历里重要度高的前 6 场，按时间排）。这是「今天最该看的那几条」的集中入口。
  - **消息面总览（2026-11-13 重构）**：页面采用「**近 14 天消息量趋势 + 我的关注 + 重点信息 + 相关消息**」四块 —— 左栏是近 14 天每天的消息量柱状趋势（口径与资讯中心一致：屏蔽词 + 四类相关性白名单，随 `GET /api/desk` 的 `news_trend` 一起返回），下方一排「**我的关注**」卡片（自选 / 持仓 / 有建仓计划的品种，点卡片进决策面板），再下方是「重点信息」面板；右栏是相关消息列表。资讯中心列表为全宽。
  - *品种口径*：贵金属域当前仅沪金 / 沪银；稀有金属按需刷新并全部保留。`stale` 字段与「陈旧」徽章用于标识暂未出现在最近采集结果中的品种。
  - **消息挂到标的上**：消息入库时按「品种全称 / 简称 → 行业别名 → 宏观词」三层规则打标（如「金价」→ 沪金，「碳酸锂」→ 碳酸锂主连，「美联储降息」→ 黄金），相关消息每条都带可点的标的标签；**点标签直接打开该标的的决策面板**。**相关消息列表按「有关联标的的排前面」排序**（同组内仍按时间倒序）。
  - **决策面板**：从「相关消息」的标的标签或「我的关注」卡片打开 —— 行情指标 + 该标的近 30 天消息 + 动作：**加入自选**、**建仓计划**、**设价格预警**（四种条件，到价写通知中心）、**记一笔持仓**（直接带着该品种进持仓表单）；消息多时一键跳到资讯中心并自动带上标的筛选。
  - **按标的筛选（深链）**：`#desk?symbol=AU0` 打开时相关消息只显示该标的，标题栏出现「只看 沪金 ✕」可一键取消。
  - **消息面（利多 / 利空按标的判定）**：每条消息在入库时就算出「对哪个标的是利多、对哪个标的是利空」——同一条「美元指数大涨」对黄金是利空、对铜毫无关系。相关消息每条都带利多 / 利空徽标与**判定依据**（命中了哪些词）；判定可在决策面板里**人工修正**，修正过的条目带 `manual` 标记，重算规则时不会被覆盖。
  - **建仓计划**：为自选或持仓标的设定**目标价（止盈）、止损价、计划均价、分批建仓价位**（价位 + 占比，占比合计必须 100%），并给出「可下手 / 待触发」批次提示、距目标与距止损的空间、盈亏比；计划按账号隔离，存在 `trade_plans` 表。**入口有两处**：决策面板的「建仓计划」按钮，以及「持仓与计划」页的**建仓计划区**（列表 + 新建 / 编辑 / 删除）。
  - **3 个标签页**：**投资总览**（消息面总览）、**实时行情**（贵金属报价）、**稀有金属研究**（稀有报价 · 材料联想）。标签用 `#desk?tab=xxx` 路由，刷新、前进后退都保持；旧书签 `#quote` / `#rare` / `#metals` 会跳到对应标签，`#dashboard` / `#screen` 归到投资总览，`#acquire-news` / `#acquire-metal` 归到 `#acquire`。
  - **底部**：整页静默刷新按 `Math.max(15, live_sec || 10)` 秒，**≥15 秒**（默认配置 10 秒）并保持滚动位置。持仓明细与财经事件明细分别在「持仓与计划」「财经日历」页查看，总览只保留标的维度的一列汇总，避免同一份数据在两处口径打架。

- **数据采集（配置中枢）**：侧边栏「数据采集」为**单页 `#acquire`**，页内用「消息数据 / 贵金属数据」**胶囊标签**切换两个数据域（无二级菜单）；每域包含「状态条 → 采集设置 → 数据源 → 最近采集」：
  
  - **状态条**：域运行状态（运行中 / 已关闭）、采集频率、下次执行倒计时与上次执行结果，以及本域「立即采集」「保存」按钮；数据源启用数 / 近 7 天成功率 / 平均耗时 / 异常任务数 / 今日入库量等统计由 `GET /api/acquire/config` 的 `stats` 返回。
  - **采集设置**：任务启停与**按间隔 N 秒**（5~86400）、关键词 / 频道 / 单源条数 / 保留天数等常用参数，其余参数收进「高级设置」（**默认展开**，仍可手动折叠）；改动后面板右上角「保存」按钮亮起并显示「保存 · N 项改动」。**每日定点 HH:00（`run_at_hour`）、单项 / 整域恢复默认值**均为后端能力（`POST /api/acquire/config` / `POST /api/acquire/params/reset`），当前前端未暴露
  - **数据源**：启停开关、单源连通性测试（耗时以 toast 提示）、状态（未测试 / 正常 / 异常）与消息域的**近 7 天入库条数**；批量连通性测试为后端 `POST /api/acquire/test-all`，当前前端未暴露
  - **采集参数**：27 项参数按域独立、按用途分组（消息域 16 项、贵金属域 11 项；常用项直显、其余收进「高级设置」），**控件名一律短标签（≤3 字）、完整说明走悬停 title**；保存后由后端采集逻辑直接读取，详见「数据采集」章节的参数表
  - **最近采集**：面板默认展开，展示最近 **10 条**（`page_size=10`，可选 10 / 20 / 50 / 100），支持刷新和分页；后端 `GET /api/acquire/logs` 支持更细的筛选，`POST /api/acquire/logs/clear` 可按条数清理。每一次采集都会写入一条 `fetch_logs` 记录。
  - **配置导入导出**：`GET /api/acquire/export` 与 `POST /api/acquire/import` 提供 JSON 备份 / 迁移，当前前端采集页未暴露入口（见 API 章节）

- **实时行情**（投资总览标签页）：**统计卡（涨跌家数 / 平均涨跌幅 / 领涨领跌 / 金银比）+ 12 列报价表 + 银行金价区块**三层结构。
  
  - *报价表*：品种、最新价（副行带买/卖价）、涨跌额、涨跌幅（带涨跌色条）、今开 / 最高 / 最低 / 昨收、振幅、成交量（副行带持仓量）、报价时间、操作；**点表头可排序**（最新价 / 涨跌额 / 涨跌幅 / 振幅 / 成交量，再点切换升降序）。类别与市场下拉按后端实际返回的品种动态生成（隐藏的市场不会出现在选项里）。
  - *缺失值口径*：新浪没给的字段（入库为 0）一律显示灰色「—」；真实平盘显示灰色 `0.00`（不着色）。缺失值不会被渲染成红色「+0.00%」。
  - *陈旧标记*：某品种不在最近一次采集结果里时整行降透明度并打「陈旧」徽章，避免把过期价当实时价。
  - *轮询不重绘*：按服务端间隔（默认 10 秒）轮询时**只更新变化的单元格、不重建 DOM** —— 横向滚动位置、文字选中、行 hover 全部保留；银行金价区块只在进页与手动刷新时渲染。
  - *品种池*：贵金属当前仅 `AU0,AG0`（沪金 / 沪银）；稀有金属品种仍在「品种管理」中自由增删。
  - *只展示在采集的品种*：`/api/metals` 按「采集品种」配置过滤 —— 未在采集配置中的品种不展示，避免过期价格被误读为实时价。配置为空（什么都不采）时不加过滤。
  - *统计图*：页面顶部统计卡使用后端 `stats` / `derived` 字段，详细图表集中在逐品种数据弹窗中。
  - *详细数据*：任一品种可打开详情弹窗 —— 关键指标网格、**日 K 蜡烛图 + 成交量**、**5 分钟分时图**（按交易日 09:00 → 次日 02:30 取数）、近 30 个交易日**明细数据**、本机采集轨迹。

- **稀有金属研究**（投资总览标签页）：**品种可自行配置**（默认碳酸锂 / 工业硅 / 沪镍 / 沪锡 四个有连续公开报价的战略金属主连），页面右上「品种管理」可增删改品种并用「检测」验证代码是否真能取到行情与 K 线；报价表与近 60 日迷你走势；右上角有「材料联想」入口按钮，跳到独立菜单页 `#material`。`/api/rare/scenarios` 为报价表 MA20、近 60 日走势与 K 线弹窗提供 `tech` / `kline_points` 技术指标数据。

- **材料联想（独立菜单 `#material`，2026-11-13 新增）**：输入行业 / 场景词，**反查最相关的金属与材料**；也可直接输入材料名**反查它的用途与配套材料**。左侧是**场景目录（39 个场景）+ 材料链（14 条）+ 材料类别（6 类 / 60 种材料）**导航，右侧是搜索 + 工具条 + 结果表 + **材料详情面板**。
  
  - **场景 → 材料**：支持组合查询（`AI 液冷`、`光伏 硅`），主场景满权、次场景折半；结果给出**相关度**（知识库关联强弱，不代表涨跌）、**命中场景 / 材料链标签**、**用途与关联逻辑**、**近 7 天库内资讯条数**（真实统计，没有就是 0，不估算）、**行情与一键接入**。
  - **材料 → 场景**：点材料名打开详情 —— 用在哪些场景（带强度条）、属于哪些材料链（带链上角色）、配套材料（常一起出现）、当前行情与「以它为起点再联想」。
  - **材料链联动**：查「碳酸锂」会顺着**锂电材料链**带出镍 / 钴 / 石墨 / 磷等配套材料；知识库共 14 条链（锂电 / 半导体 / 光伏 / 稀土永磁 / 铂族 / 钢铁合金 / 高温合金 / 硬质合金 / 氢能 / 核材料 / 光学 / 战略小金属 / 基本金属 / 农业化肥）。
  - **可一键接入的材料扩充到 10 种**（全部实测新浪行情 + 东财 K 线可用）：铜 / 铝 / 铅 / 锌 / **锡** / **镍** / **氧化铝** / 多晶硅 / **工业硅** / **碳酸锂** / 锰硅；没有稳定免费报价的材料给「手动接入」，**绝不伪造价格**。

- **消息中心（核心）**：按关注关键词抓取多平台财经资讯，自动归入 **股市 / 基金 / 债券 / 贵金属 / 宏观 / 外汇 / 房地产 / 政策 / AI·算力 / 综合** 频道；提供**全文搜索（命中高亮）**、**时间范围筛选**（今日 / 近 3 天 / 近 7 天 / 近 30 天）、**排序**（最新 / 最早 / 命中度）、**频道与来源筛选**、**按日分组**、**页码分页与每页条数可调**；列表为**全宽**，支持**单条收藏 / 批注 / 删除**与**单条情绪人工修正**（在标的决策面板）；支持**利多利空筛选**（全部 / 只看利多 / 只看利空 / 只看中性）、**「只看重点消息」筛选**（也可深链 `#news?key=1`）与顶部**「一键已读」**（清掉通知中心里全部重点消息的未读点）。重点消息卡片顶部带**红色「简报」高亮行**（方向 + 影响标的 + 事件类型），原文摘要退成灰色小字。

- **消息抓取与定时**：部署到 Cloudflare 后由 `[triggers] crons = ["* * * * *"]` **每分钟**唤醒一次，由**各任务自身的间隔配置**（`fetch_tasks`）决定是否执行，间隔可在「数据采集」页配置为 **5～86400 秒**。标题归一化后生成指纹去重，并过滤「真金白银」等成语假阳性。

- **K 线技术指标**（详细数据页）：日K / 周K / 月K 三种周期可切换；主图可叠加 **MA5/10/20/60** 与 **BOLL(20,2)**，副图可切 **成交量 / MACD(12,26,9) / RSI(6,12,24) / KDJ(9,3,3)**；顶部给出**指标摘要**（均线排列、MACD 所处区间、RSI 强弱、布林位置与一句话技术面倾向）与最新值。指标全部在服务端一次算好下发（序列与 K 线严格对齐、无效位为 null），口径按国内看盘软件：MACD 柱 = 2×(DIF−DEA)，RSI/KDJ 用 SMA(X,N,1) 平滑。

- **财经日历**（独立菜单）：按日期分组的**经济事件日程**（时间 / 地区 / 事件 / 重要度 / 前值 / 预期 / 公布值 / 剩余时间），支持按时间范围、地区、重要度筛选；内置 12 个常用事件模板（非农、CPI、美联储利率决议、中国 PMI 等）一键填充名称与国家；**到点前 30 分钟自动提醒**（写入通知中心 + 推送 Webhook），同一事件同一时间只提醒一次，改时间会重新计时。

- **持仓与计划**（独立菜单 `#portfolio`）：**三块** —— ① **建仓计划**（列表：品种 / 目标价 / 止损价 / 现价 / 距目标 / 盈亏比 / 状态 / 备注，支持新建、编辑、删除；新建时先从品种清单里选品种）；② **持仓明细**（录入品种 / 数量 / 成本价 / 手续费 / 建仓日，按实时行情自动计算**市值、浮动盈亏、盈亏比例**，并给出按品种的**资产分布占比**条）；③ **我的自选**（品种 / 现价 / 涨跌 / 备注，可一键进决策面板或移出自选）。持仓按账号隔离（管理员可见全部）。

- **价格预警**：支持「价格上破 / 价格下破 / 涨幅达到 / 跌幅达到」四种条件，可设**冷却时间**（默认 30 分钟，避免连续采集刷屏）；每次行情刷新后自动判定，命中写入通知中心并推送 Webhook。入口在「实时行情」页的「价格预警」按钮。
  - **推送正文不再是干巴巴一行**：包含 `品种（代码）/ 现价（涨跌幅）/ 涨跌额 / 日内开高低 + 昨结 / 触发条件 / 行情时间 / 上次触发时间`，末尾统一附 `发送时间（北京时间）`。手机通知脱离站内上下文时，也能判断这条是刚发生的还是延迟补发的。

- **通知中心 + 推送集成**：顶栏铃铛显示未读数（每 60 秒轮询一次），点击展开最近通知（可单条已读 / **一键已读** / **重点已读**），抽屉内有「全部 / 未读 / 重点」子筛选与各自计数；重点消息条目只显示标题与时间（完整研判见资讯中心原消息）；推送通道配置在独立的「**通知与集成**」菜单（`#notify`，2026-11-13 从系统设置拆分出来），支持 **企业微信 / 钉钉 / 飞书机器人 / ShowDoc 推送 / 通用 JSON Webhook**，以及 **Telegram 机器人 / 微信推送（PushPlus）/ Bark（iOS 推送）** 三种第三方集成 —— 只需粘贴群机器人地址或 Token，无需申请应用；通道会记录最近一次推送的状态与返回内容，便于排错；每种类型单独提供「测试」按钮，可只向该通道发一条验证是否连通。
  - **ShowDoc 推送怎么配**：在 ShowDoc 官网开通「推送服务」后会拿到一条专属地址（形如 `https://push.showdoc.com.cn/server/api/push/<key>`），在「通知与集成 → 添加通道」里选「ShowDoc 推送」，把地址粘进「专属推送地址」即可。系统按官方要求用 **POST 表单** 提交 `title` + `content`（GET 传 `text` / `desp` 会被服务端判为「标题和内容都不能为空」，这是该接口最容易踩的坑）；正文为空时用标题兜底。失败判定同时看 HTTP 状态码和返回体里的 `error_code`，因为 ShowDoc 成功与失败都返回 200。
  - **推送正文口径（全通道统一）**：重点消息推送带 `简明摘要 / 重点分 + 方向 + 影响标的 / 来源 + 频道 / 发布时间 / 传导链 / 挑选依据 / 原文链接`；财经日历提醒带 `公布时间 + 距今几分钟 / 重要性 / 预期 / 前值 / 公布值`；所有推送末尾都附 `发送时间（北京时间）` 页脚。

- **重点消息 → 通知中心（全量 + 点亮 + 看过即已读）**：资讯中心被算法点亮为「重点」的消息（综合分 ≥ 55 且有方向或强信号）**全部**写进通知中心 —— 不再只推每次新入库的前 5 条。
  
  - **简明摘要**：每条重点消息生成一句 `key_brief`（`发生了什么 → 偏涨/偏跌 → 影响谁 · 事件类型`，≤ 70 字），资讯卡片上用高亮行展示，通知正文第一行也是它；**只拼已有字段，不编造原文没有的信息**（无研判就不给方向，多空交织标「多空分歧」）。
  - **点亮**：重点通知以未读（橙色底 + 红色色条 + 「重点 / 未读」角标）进入通知中心，铃铛角标同步计数。
  - **看过即已读**：资讯中心里重点消息滚入视口（≥60% 可见）即自动把对应通知标记为已读；点通知本身也会消除未读；资讯中心顶部另有「**一键已读**」把全部重点通知一次清空。
  - **幂等**：`dedup_key = "news_key:" + 消息 hash` + 唯一索引 → 重复同步不会重复插入，**已读过的不会被重新点亮**；采集完成、冷启动、规则版本变更后自动全量同步（保留窗口 7 天），也可手动 `POST /api/notifications {action:"sync_key"}`。
  - **快速通道（读 / 写配额保护）**：`migrate()` 在**每个 API 请求前**都会跑，所以同步函数先用一条只读「同步令牌」短路 —— 令牌 = `重点打分版本 | 研判版本 | 正文格式版本 | news 表最大 id`，没变就说明既没有新消息、规则也没改，直接返回（只读 1 行）。令牌变了才走原来的 COUNT 判断「有没有还没进通知中心的重点消息」+「正文格式版本有没有变」，两样都没有同样**不做任何写操作**；正文格式变更用 `settings.news_notify_body_ver` 戳记，只全量刷新一次。避免每次请求都写上百条通知把 D1 写配额打爆，也避免那条 `COUNT + NOT EXISTS` 关联扫描把读配额打爆（实测一天 2.39M 行读取）。
  - **聚合缓存 + 轮询节奏（读配额保护）**：投资总览 `/api/desk` 与资讯中心 `/api/news` 的**统计聚合**（总量 / 今日 / 重点 / 收藏 / 情绪分布 / 频道来源分布 / 14 天趋势 / 热词）由同一个 `newsStatsBundle` 产出一份缓存，**两个页面共用**，在 isolate 内缓存 **3 分钟**（键 = 过滤条件 + 参数 + 日期），**列表与行情不缓存**，新消息依旧实时出现。聚合本身也从「5 个 COUNT + 3 个 GROUP BY 各扫一遍表」合并成「1 条聚合 + 1 条明细」，分布 / 趋势 / 热词在 JS 里算，单次未命中从约 9,800 行降到约 2,000 行。前端轮询下限：总览 / 资讯 **30 秒**，行情页仍按配置（默认 10 秒），铃铛 60 秒；**标签页在后台 / 窗口最小化时暂停轮询**，切回来最迟一个周期补上。叠加「屏蔽词并入 `relevant`」后的 `relevant = 1` 索引命中，开着页面不动时的读行数从每小时几十万行降到每小时 3~5 万行。
  - **外部通道仍限量**：写入通知中心不设上限，但推送到企业微信 / 钉钉 / 飞书的**只有本次新采集**的重点消息，按综合分降序取「外部通道推送上限」条（默认 5），避免一次性刷屏。

- **系统设置**：可修改系统名称（默认「稀有金属投资咨询平台」）；采集相关配置（关键词 / 数据源启停 / 抓取量 / 频道 / 留存）统一收敛到「数据采集 → 消息数据」，此页只保留跳转入口，避免两处配置打架。**数据源启停以 `data_sources` 为唯一事实来源**。通知推送通道已迁到独立的「通知与集成」菜单。所有接口均免密钥。

- **用户管理**：管理员 / 普通用户 / 访客三种角色 + 按钮级权限（admin 全量 / user 7 项 / visitor 仅 `news.view` + `market.view`）；**公开注册已下线，账号由管理员在「用户管理」创建**。**空库全新部署必须手工写入首个 admin**（密码格式见「部署」章节）；改密 / 停用账号会 `token_version+1`，立即吊销该用户已签发的旧 token。

## 技术结构

```text
浏览器
  └─ Cloudflare Worker
       ├─ static/   静态前端 (HTML/CSS/JS SPA)
       ├─ worker.js API、认证、资讯抓取、行情与快照采集、数据采集调度、用户与设置
       └─ D1 数据库 (SQLite)
```

使用 Workers Static Assets 提供前端文件，`/api/*` 请求由 Worker 处理；`[triggers] crons` 为 **单一唤醒入口** `* * * * *`（每分钟一次），每次唤醒后由 `fetch_tasks` 表中各任务的**间隔配置**（默认 30 / 10 / 10 / 10 分钟，范围 5～86400 秒）判断哪些任务到期并执行 —— 因此调整间隔或启停任务都无需改动 `wrangler.toml` 或重新部署。

## 图表引擎

所有统计图统一由 **Apache ECharts 5.5.1** 渲染（`static/js/vendor/echarts.min.js`，约 1.0 MB，随项目本地托管）；但**图标字体 FontAwesome 6.5.1 走 cdnjs CDN**（`static/index.html` 的 `<link>` 引用）。即：图表引擎自身是本地文件、离线可用，图标字体仍需外网，离线部署时图标会退化为方块 —— 不能笼统说「全部资源本地化」。

**为什么选它**：ECharts 是 GitHub 上 star 数最高的国产可视化库（6 万+，Apache 基金会顶级项目），也是国内金融、政企数据看板的事实标准。相比手写 SVG，它直接提供坐标轴刻度、十字光标、tooltip、图例开关、框选缩放这些细节，且 K 线 + 多副图联动是它的官方示例形态。

| 图表        | 实现方式                                                                                                                             | 位置                                     |
| --------- | -------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| **K 线**   | `candlestick` + 多 `grid` + `dataZoom`（inside + slider），主图叠加 MA / BOLL，副图可选成交量 / MACD / RSI / KDJ，`axisPointer.link` 让十字光标在主副图间联动 | 品种详情弹窗                                 |
| **横向对比柱** | `bar` + `inverse` 类目轴，带百分比刻度与数值标签                                                                                                | 当日涨跌幅、当日振幅、逐次采集环比                      |
| **多系列折线** | `line` + `showSymbol:false`，长序列自动启用 `dataZoom`                                                                                   | 多品种联动走势、金价采集走势、绝对价位、分时、采集轨迹            |
| **竖向柱**   | `bar` + `minInterval:1`                                                                                                          | 投资总览 · 近 14 天消息量（2026-11-13 从消息中心右栏搬来） |

> 图表能力集中在品种详情弹窗和投资总览趋势：详情页使用 K 线、分时、成交量与技术指标，投资总览使用近 14 天消息量柱状图；稀有金属表格的迷你走势保留 SVG 实现。

**几个实现要点**

- **声明式挂载**：绘图函数只返回一个 `<div class="echart">` 占位符并把配置存进队列，`MutationObserver` 侦测到它进入文档后再 `echarts.init` —— 因此所有 `innerHTML` 赋值处都不需要改动，也不会在容器还是 0 尺寸时初始化。
- **实例回收**：每次挂载先遍历已注册实例，`document.contains(dom)` 为假的直接 `dispose()`，避免切换视图后残留。
- **涨红跌绿**：`CHART_UP = #dc2626`、`CHART_DOWN = #16a34a`，与 CSS 变量 `--up` / `--down` 一致（国内习惯，与欧美相反）。
- **K 线纵轴不写死范围**：`dataZoom` 默认只显示最近 120 根，纵轴交给 ECharts 按**当前可见数据**自适应。早期把 min/max 固定成全量区间，结果被 2025 年的历史高点（1258）拉高，近期蜡烛（830~1000）全挤成一条线 —— 这是实测踩到的坑。
- **SVG 兜底保留**：`vendor/echarts.min.js` 加载失败时，三个绘图函数会自动回退到原来的手写 SVG，页面不会白屏。
- **迷你走势仍用 SVG**：稀有金属表格里的 `sparkSvg`（88×24、无坐标轴、无交互）刻意保留矢量实现 —— 这个尺寸下 Canvas 不如 SVG 清晰，且省掉每行一个实例的开销。

升级方式：把新版 `echarts.min.js` 覆盖到 `static/js/vendor/` 即可，无需改调用代码。

## 数据说明

仓库仅保留 `schema.sql`：包含认证 / 菜单设置、资讯、行情与品种、采集配置、通知预警、持仓决策、财经日历共 **21 张表**的完整结构、索引与默认数据源 / 任务 / 品种 / 菜单 / 设置。不包含任何真实用户、密码哈希或私有数据。

**没有预置管理员，且公开注册已下线**：`publicAPI = ["/api/login","/api/auth","/api/health"]`，无 `/api/register`；`migrate()` 与 `schema.sql` 都不会 `INSERT INTO users`。账号一律由管理员在「用户管理」创建，**空库全新部署必须手工写入首个 admin**（密码格式 `pbkdf2$100000$salt$hash`，或旧格式 `sha256(pwd:salt)` 由 `worker.js` 登录时自动升级），详见「部署」。

## 部署要求

- Cloudflare 账号（Workers + D1 + Static Assets）
- Node.js 18+ 与 `npx wrangler`
- 一个随机 `JWT_SECRET`（`openssl rand -hex 32`），**长度必须 ≥ 32 字符**（`worker.js` 的 `jwtSecret()` 会校验，不足则视为未配置，签发 token 时抛错）
- `wrangler.toml` 的 `compatibility_date = "2026-07-15"`，`database_id` 必须配置为目标 D1 数据库 ID

## 一、下载并登录 Cloudflare

```bash
npx wrangler login
```

## 二、创建 D1 数据库

```bash
npx wrangler d1 create resource-manager
```

把输出的 `database_id` 填入 `wrangler.toml` 的 `database_id`（同时可按需修改 `name` / `database_name`）。如果配置文件中已有目标数据库 ID，则无需重复替换；`compatibility_date = "2026-07-15"` 保持不动即可。

## 三、初始化数据库

```bash
npx wrangler d1 execute resource-manager --remote --file=./schema.sql
```

> 这一步不是必须的：Worker 的 `migrate()` 会在首个请求时幂等建齐 **21 张表**并写入默认数据源 / 任务 / 菜单 / 参数，空库直接 `deploy` 也能跑起来，**建议直接让 `migrate()` 自愈**。`schema.sql` 用于「显式初始化」或作为建库快照（例如想先用 SQL 审一遍结构时）。**注意种子优先级**：`migrate()` 的默认数据全部用 `INSERT OR IGNORE`，若先执行本 `schema.sql`，则本文件写入的种子会「胜出」且 `migrate()` 不会覆盖（菜单例外：`migrate()` 用 `UPDATE` / `DELETE` 强制纠正）；因此两个文件的种子必须保持一致。

## 四、配置登录密钥

`JWT_SECRET` 从 env 读取，**长度必须 ≥ 32 字符**（`worker.js` 的 `jwtSecret()` 对长度不足的值返回空串）：

```bash
openssl rand -hex 32          # 生成 64 位十六进制随机串
npx wrangler secret put JWT_SECRET
```

本地开发时该键写在 `.dev.vars`（唯一需要的键），线上用 `wrangler secret put` 写入，不要提交进仓库。

## 五、部署

```bash
npx wrangler deploy
```

打开返回的 `https://<worker>.workers.dev` 即可访问登录页。

> **⚠️ 空库全新部署必须手工写入首个管理员**：本平台**不开放注册**（`publicAPI = ["/api/login","/api/auth","/api/health"]`，无 `/api/register`），`migrate()` 与 `schema.sql` 都**不会** `INSERT INTO users`。请用 `wrangler d1 execute` 手工写入一条 admin 记录：`password` 列格式为 `pbkdf2$100000$<salt>$<hash>`（`<salt>` 为 16 字节随机值的 base64，`<hash>` 为 PBKDF2-HMAC-SHA256 / 10 万次迭代 / 32 字节派生结果的 base64）；也可先写旧格式 `sha256("<密码>:<salt>")`，首次登录时 `verifyPassword()` 会自动升级为 PBKDF2。示例（把 `<...>` 换成实际派生值）：
> 
> ```bash
> npx wrangler d1 execute resource-manager --remote --command "INSERT INTO users(username,password,salt,role,enabled,token_version) VALUES('admin','pbkdf2\$100000\$<salt>\$<hash>','<salt>','admin',1,0)"
> ```
> 
> 之后在「用户管理」里创建其他账号。改密 / 停用账号会 `token_version+1`，立即吊销该用户已签发的旧 token。

## 六、本地开发

创建 `.dev.vars`（已被 git 忽略，**仅此一个键**）：

```text
JWT_SECRET=<请用 openssl rand -hex 32 生成>
```

> `JWT_SECRET` 至少 32 字符；长度不足时 `jwtSecret()` 返回空串，登录签发 token 会失败。

初始化本地 D1 并启动：

```bash
npx wrangler d1 execute resource-manager --local --file=./schema.sql
npx wrangler dev --port 8912 --ip 127.0.0.1
```

打开 `http://127.0.0.1:8912`。如需触发定时任务，访问 `http://127.0.0.1:8912/cdn-cgi/local/scheduled`，或启动时加 `wrangler dev --test-scheduled` 后用同一 URL 触发。

> 提示：默认端口 `8787` 常被其他 Wrangler 项目占用，可固定用 8912 或任意空闲端口；若机器设置了 `http_proxy`，命令行 `curl` 访问本地需加 `--noproxy '*'`，浏览器直连不受影响。`wrangler.toml` 中的 `name` / `database_name` 沿用 `resource-manager` 以保持既有本地状态兼容，新建部署可自行改名。种子优先级同上：本地若先跑 `--file=./schema.sql`，该文件的种子会胜出，建议直接让 `migrate()` 自愈。

## 七、数据库表

当前共 **21 张表**（与 `worker.js` 的 `migrate()` 一致）：

| 表                   | 说明                                                                                                                                                                                                                                                                                                          |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## 数据采集（按数据域配置：消息数据 / 贵金属数据）

> 数据采集页按「状态条 → 采集设置 → 数据源 → 最近采集」组织两个数据域；完整能力以当前 API 表为准。

「数据采集」是系统的**采集控制中枢**，所有"从哪取、什么时候取、取什么、手动取不取"都在这里配置。

侧边栏「**数据采集**」是**单页 `#acquire`**（9 项平铺导航、无二级菜单），页内用「**消息数据** / **贵金属数据**」**胶囊标签**切换两个**数据域**，每个域独立管理自己的数据源、定时任务、采集参数与日志：

| 胶囊标签      | 数据域   | 覆盖内容                       | 数据源                             | 定时任务                  |
| --------- | ----- | -------------------------- | ------------------------------- | --------------------- |
| **消息数据**  | news  | 全网财经资讯抓取                   | 东方财富搜索、新浪 7×24、华尔街见闻 7×24       | 财经资讯抓取                |
| **贵金属数据** | metal | 实时报价 / K 线 / 金价快照 / 银行官网金价 | 新浪实时行情、东方财富历史 K 线、交通银行 1 个银行官网源 | 金价快照采集、贵金属行情刷新、银行金价采集 |

### 定时任务（4 个，间隔可配置）

| 标识                | 名称      | 所属域   | 默认间隔      | 作用                                                      |
| ----------------- | ------- | ----- | --------- | ------------------------------------------------------- |
| `metal_snapshot`  | 金价快照采集  | 贵金属数据 | 30 分钟     | 拉取实时行情，生成一条金价快照（环比涨跌、异动等级、处理结论、全品种明细）                   |
| `metal_quote`     | 贵金属行情刷新 | 贵金属数据 | 10 分钟     | 拉取实时报价，更新行情看板的现价 / 涨跌幅 / 振幅 / 持仓量等字段                    |
| `news_crawl`      | 财经资讯抓取  | 消息数据  | **10 分钟** | 按关注关键词抓取财经快讯，按标题指纹去重入库                                  |
| `bank_gold_quote` | 银行金价采集  | 贵金属数据 | **10 分钟** | 抓取交通银行官网贵金属行情并写入 `bank_gold_quotes`（失败标记 stale，保留上次成功值） |

四个任务的 `run_at_hour` 默认均为 `-1`（按间隔执行，不做每日定点）。**间隔默认 1800 / 600 / 600 / 600 秒（30 / 10 / 10 / 10 分钟），均可在「数据采集」页按秒配置（最小 5 秒）**；`wrangler.toml` 的 cron 每分钟唤醒一次，实际以 `fetch_tasks` 表为准。新任务用 `INSERT OR IGNORE` 插入，**不会覆盖已有 3 个任务被手动调整过的间隔**。银行金价采集也可在「实时行情」页点银行区块的「刷新」按钮手动触发（`POST /api/bank-gold/refresh`）；采集页「立即采集」的贵金属域任务列表已包含 `bank_gold_quote`。

- **调度模式（后端口径）**：`fetch_tasks.run_at_hour = -1` 为**按间隔**（5 ~ 86400 秒，`next_run_at = last_run_at + interval`）；`run_at_hour` 取 0~23 时为**每日定点**，`next_run_at` 对齐到下一个该时刻，适合"每天开盘前抓一次"这类需求，而不用去凑 1440 分钟。当前采集页**只提供「按间隔」输入**并固定写入 `run_at_hour=-1`，每日定点需通过 `POST /api/acquire/config` / `POST /api/acquire/import` 设置，前端未暴露该控件
- **可停用**：停用后该任务不再被 cron 触发，`next_run_at` 置空；采集页对应「启用自动采集 / 启用金价快照 / 启用行情采集」开关
- **调度模型**：`wrangler.toml` 只有一条 `* * * * *`（每分钟）唤醒入口。按间隔的任务用 `last_run_at + interval` 判断到期；定点任务用 `next_run_at <= now` 判断。**因此调整间隔或模式都无需改配置文件、无需重新部署**
- **失败保护（参数「失败」）**：每次失败把 `fail_streak` +1，成功即清零；达到「失败」阈值（默认 5 次）后**自动停用任务并推一条通知**。一个失效的上游如果不刹车，会按间隔无限重试（10 分钟一次 ≈ 每天 144 次），既刷日志也耗额度。修复后在采集页重新打开启用开关并保存即可，`fail_streak` 自动归零
- **倒计时**：`next_run_in_sec` 由后端算好下发，采集页状态条只在加载 / 刷新配置时渲染一次（旧版每秒原地刷新文本的定时器已取消）。若 `next_run_at` 已过期（例如进程停摆过），显示「已到期」而不是负数
- **自愈**：某次唤醒失败或上游抖动，下次唤醒会重新判断是否到期并补采，不会断档

**数据保留面板（采集页顶部独立区，2026-11-16 新增）**

用途：控制 D1 数据库容积，过期数据自动清理，也可手动立即清理。集中管理上面散落在两域的留存参数，分三组：

- **自动保留**：消息保留天数、日志保留天数 —— 在每次采集时自动删除超期数据。

面板有独立「保存」按钮，改动后分别提交到 news / metal 两域的 `acquire_options`（复用 `POST /api/acquire/config`），与域内参数互不干扰。这些参数原本分散在消息采集顶栏和贵金属高级设置里，已迁到此面板（域内不再重复渲染）。

1. 「品种」框内填符号（当前为 `AU0, AG0`，留空表示全部采集）

**关于「屏蔽词被清空却开始拦住所有资讯」**（已修）：`parseNewsKeywords()` 在空值时会把参数回退成默认关键词列表 —— 这对「关注关键词」是想要的行为，但用在「屏蔽词」上等于「把所有关键词都设成屏蔽词」。现在两者分开：关键词走 `parseNewsKeywords`（空 → 默认词），屏蔽词走 `splitList`（空 → 空，不拦任何东西）。

## 投资工作台与「消息 → 标的」联动

### 标的打标规则

消息入库（自动抓取与手动录入都一样）时给 `news.symbols` 写入关联标的，规则分三层，最多贴 4 个：

1. **品种全称 / 简称**：按词长倒序匹配，命中后从文本里剔除，避免「工业硅」又被「硅」重复命中。
2. **行业别名**：命中即落到该类别 —— 黄金（金价 / 沪金 / 金饰 / 央行购金）、白银、锂（碳酸锂 / 锂矿 / 锂电）、硅（工业硅 / 多晶硅 / 硅料 / 硅片）、镍、锡、铜、铝。
3. **宏观词**：美联储 / 降息 / 加息 / 美元指数 / 实际利率 / 非农 / CPI / 通胀等默认只补黄金（利率与美元是金银的核心定价变量），不扩散到工业金属。

一个类别落到哪些合约是写死的（黄金 → 沪金，白银 → 沪银，其余类别一个），避免一条消息把半个市场都贴上。**新增或改名品种后**，可在消息中心调用 `{"action":"retag"}` 让历史消息按新词表重标一遍。

## 消息的利多利空判定（按标的）

### 为什么要按标的判

同一条消息对不同标的方向可以完全相反：「美元指数大涨」对黄金是**利空**，对铜毫无关系；「碳酸锂减产」对碳酸锂是**利多**，对黄金毫无关系。所以情绪不能给整条消息贴一个标签，必须**逐个标的**算。

`news.sentiment_map` 存的就是这张明细表：

```json
{
  "AU0": { "label": "bullish", "score": 4.9, "hits": ["重返", "提供支撑"], "manual": 0 },
  "AG0": { "label": "neutral", "score": 0, "hits": [], "manual": 0 }
}
```

`news.sentiment` 是整体标签，按**标的投票**得出（利多的标的多就是利多；`manual` 权重加倍），与人工修正后的汇总口径完全一致 —— 重算时整体标签不会莫名跳变。

### 判定流程

1. **切句**：按 `。！？!?` 切分，句内保持主谓完整（否则「直线拉升！现货黄金重返4000」会被拆散）。标题与摘要**分开判定**，摘要权重 0.6 —— 标题是主旨，摘要不该盖过标题。
2. **找方向词**：约 90 个方向词分四组（价格走势 / 资金持仓 / 供需产业 / 政策预期），带权重；否定词（不 / 未 / 无 / 没有 / 难 / 非 / 尚未）在**相隔 1 字以内**时把方向**取反**（「美联储不愿降息」→ 降息取反）。
3. **找主语**：品种全称/简称（最具体）> 行业别名 > 泛称（贵金属）> 宏观主体。**方向词与主语按中文语序就近配对**（主语在左边优先，左边没有再回退到全局最近），并设 12 字距离上限，避免跨小句误绑。
4. **宏观主体方向取反**：美元指数 / 实际利率 / 通胀**走强 = 贵金属走弱**，方向词要取反；加息、降息这类**自带确定含义的政策词不参与取反**。
5. **干扰主语**：油价、A股、港股、美股、股指等方向与贵金属无关的主语会**吃掉**靠近它的方向词（「油价暴跌缓解通胀压力」不该算成黄金利空）。
6. **并列主语**：「金价银价大涨」里金价与银价并列，方向词对两者都成立。
7. **噪声短语**：「真金白银」「金银价格」等成语/固定搭配会被等长替换掉，避免误打标成白银消息。
8. **只有已打标的标的参与判定**：一条讲苹果降级的消息与我们无关，不会被算成利空。

## 金价快照采集

系统通过 Cloudflare Cron 每分钟唤醒，实际由 `fetch_tasks` 中的 `metal_snapshot`（默认 30 分钟）、`metal_quote`（默认 10 分钟）、`news_crawl`（默认 10 分钟）与 `bank_gold_quote`（默认 10 分钟）四个任务按各自间隔执行。任务间隔可在「数据采集」页配置为 5～86400 秒；低于 60 秒的部分由页面访问补采。

`metal_snapshot` 将采集结果写入 `metal_snapshots`，银行金价任务写入独立表 `bank_gold_quotes`，两条链路互不混用。

## 银行金价（官网一手数据）

系统目前只接入交通银行官网的上海黄金交易所行情。银行数据不并入 `metal_quotes`，使用独立表 `bank_gold_quotes`、独立 API 和行情页独立区块；所有官网缺失的数值字段保留为 `NULL`，前端显示为「—」，不做推算。

### 架构：独立表 + 独立 API + 行情页独立区块

银行数据**不并入 `metal_quotes`**，原因是两张表的字段口径不同：银行官网数值允许 `NULL`，而交易所行情表使用固定字段与默认值。系统因此使用独立表 `bank_gold_quotes`（数值列允许 NULL）、独立 API `/api/bank-gold`，并在「实时行情」页提供独立区块。每条官网记录以 `symbol` 为主键，保留基础价和有效的 Au 系合约行情。

每条官方记录各自一个 `symbol` 主键，**不做「每源只留 1 条」的二选一**：`Au99.99` 基础价 1 条 + `Au` 系合约 N 条，实测 **4~5 条**（随品种停牌波动，`Au99.95` 全 0 时会被过滤），全部保留。行数不做任何写死断言。

### 1 个官网源

| source_key    | 名称           | 端点（https）                                   | 入库口径                                    | 官网缺口                         |
| ------------- | ------------ | ------------------------------------------- | --------------------------------------- | ---------------------------- |
| `bocom_metal` | 交通银行 · 贵金属行情 | `www.bankcomm.com/SITE/getNobleMetalNew.do` | 上金所 `Au99.99` 基础价 + `Au*` 合约行情（元/克（推断）） | **涨跌幅字段确认不可用**、无买卖价、无投资金条零售价 |

源为 UTF-8（**禁止 GBK / `TextDecoder('gbk')`**，会毁掉中文），`fetchWithTimeout(url, {headers:{"User-Agent": NEWS_UA}}, 7000)` + 1 次重试；Workers `fetch` 自动解压 gzip，直接 `await r.text()`，不手工解压。

### 口径差异对照（不可直接横向比较）

| 源                | 价格含义    | 单位      | 涨跌                  | 官方报价时间                    | 备注                                                                           |
| ---------------- | ------- | ------- | ------------------- | ------------------------- | ---------------------------------------------------------------------------- |
| 交行 `Au99.99` 基础价 | 上金所基础价  | 元/克（推断） | —                   | `metalList.upTime`        | 非交行零售报价、非投资金条售价；官网未提供涨跌                                                      |
| 交行 `Au*` 合约      | 上金所合约行情 | 元/克（推断） | **仅官方涨跌额** `upDown` | `quoteDate` + `quoteTime` | `change_pct` 永久 `null`；`closePrice` 0.00 占位不采用；排除 `Ag(T+D)` 与全 0 的 `Au99.95` |

**交行涨跌幅已确认不可用（不是待确认项）**：两次独立抓取（10:14 与 10:40）显示 4 个有效品种的 `upDownRate` 全部恒为 `"-0.01%"`，而 `upDown/lastClose` 自算约 −1.7%（如 `Au99.99` −15.42 / 883.42），差约 **180 倍**；停牌的 `Au99.95` 为 `"0.00%"`。这是官网错误 / 占位字段，不是待确认项。因此 `change_pct` **永久 `null`**，`note` 与 `caliber` 一律写「官网涨跌幅字段不可用，未展示」；`change` 用官方 `upDown` 是真实值，保留；**也不允许用 `upDown/lastClose` 反推**（T+D 行涨跌基准是昨结算价而非 `lastClose`，算术不自洽）。另注意 `metalNewList` **没有 `upTime`**，只有 `quoteDate` + `quoteTime`；`upTime` 只存在于 `metalList`。`RSP_BODY.realIp` 是请求方出口 IP，禁止入库与展示。

### 缺失字段如何展示

- 所有**数值列**（`price/bid/ask/change/change_pct/prev_close/open/high/low/weight_g`）的「官网无此数据」一律写**真 `null`**，禁止用 `0` 或 `''` 代替；前端统一 `v == null || v === '' ? '—' : metalNum(v)` 判空，**显示 `—` 时不得着色**（不调用 `chgColor` / `chgSign` / `pctBadge`，也不改它们的签名）。交行源不提供买卖价，因此 `bid` / `ask` 恒为 `null`。
- `quote_stamp` 是唯一例外：`metalList` 行取 `upTime` 原文、`metalNewList` 行取 `quoteDate + quoteTime`，均 `stamp_kind='official_quote'`；若某行两者皆空则写 `''` 且 `stamp_kind='none'`（当前交行源不触发）。`collected_at` 恒为采集时刻（北京时间），列标题明确写「采集时间（非官方报价时间）」。
- `caliber` / `note` / `symbol` 等长口径文案收进产品名的 `title` 悬浮提示，表格里只留一行数据（2026-11-12 用户要求紧凑）；`status='stale'` 的行加 `text-muted`，「上次成功值」也并入 title。
- 单位官网未明示，一律带「**（推断）**」；`currency` 一律 `CNY`。**禁止任何量纲换算**（`Ag(T+D)` 与 `metalList` 银价单位相差 1000 倍，已在采集器内排除）。

### 采集与刷新

- 任务 `bank_gold_quote`（`domain='metal'`，`interval_sec=600`（`interval_min=10` 同步写），`enabled=1`，`run_at_hour=-1`，`sort_order=40`）由 cron 每分钟唤醒时按间隔驱动；`runFetchTask` 门禁为「`bocom_metal` 的 `enabled=1`」，**不复用 `sina_quote` 的开关**。
- 「实时行情」页银行区块**不做高频轮询**（官网不宜频繁抓）：进入页面加载一次 + 手动点「刷新」（`POST /api/bank-gold/refresh` → 重新 `loadBankGold()`）。下方贵金属表格的 `Math.max(5, liveSec)` 轮询保持不变，回调里不重复请求银行接口。
- 银行表格行**不绑定** `openMetalDetail`（无 K 线），不复用 `tr[data-sym]` 选择器，避免被行情表行点击监听捕获。
- 采集页「测试」按钮对 `bocom_metal` 会真实请求官网并校验解析有效性（`probeSource` 走 `collectBankSource`），不会显示「不支持连通性测试」。数据源块会展示 `data_sources.description`（口径摘要 + 缺口说明）。

### 失败降级（不写 0、不冒充新报价）

解析出 0 条即判采集失败，重试 1 次后仍失败则：不删除该 `source_key` 的已有行、不写入 `0` / 空价格，改为 `UPDATE ... SET status='stale', note=<追加「本次采集失败，显示上次成功值（采集时间 xxx）」>`。交行必须校验 `RSP_HEAD.TRAN_SUCCESS === "1"` 且 `metalList` / `metalNewList` 均为非空数组（错误路径是 HTTP 200 + `TRAN_SUCCESS:"0"` + `ERROR_CODE`），否则抛错而不是静默返回空数组。行级过滤：只收 `prodCode` 以 `Au` 开头的合约（排除 `Ag(T+D)`，其与 `metalList` 银价单位差 1000 倍），并剔除 `newPrice/openPrice/highPrice/lowPrice/averPrice` 全 0 的行（停牌占位）。

**标识符稳定性**：`Au99.99` 基础价固定为 `BOCOM_BASE_AU9999`；合约行为 `BOCOM_MKT_<prodCode 去符号大写>`（如 `BOCOM_MKT_AU100G`、`BOCOM_MKT_AUTD`）。**禁止依赖「列表首条」**，这样 `ON CONFLICT(symbol)` 重复采集不会串位。

| 出厂默认  | 代码    | 交易所 | 单位  | 产业链                |
| ----- | ----- | --- | --- | ------------------ |
| 碳酸锂主连 | `LC0` | 广期所 | 元/吨 | 锂电（正极 → 电池 → 车/储能） |
| 工业硅主连 | `SI0` | 广期所 | 元/吨 | 硅基（多晶硅 → 光伏 / 有机硅） |
| 沪镍主连  | `NI0` | 上期所 | 元/吨 | 不锈钢 / 三元前驱体        |
| 沪锡主连  | `SN0` | 上期所 | 元/吨 | 焊料 / 电子            |

- **自己加品种**：点「品种管理」→ 填代码（如 `AO0`）+ 选行情前缀（内盘期货 `nf_` / 外盘 `hf_` / 上金所延期 `gds_`）+ 名称、市场、类别、单位、产业链；东财 secid（如 `113.AOM`）可选，填了才能做情景推演。
- **先检测再保存**：「检测」会用填的代码实打实请求一次新浪行情，回显**接口返回的中文名、现价、昨收、涨跌幅**；填了 secid 还会顺带验证东财日 K（回显取到多少根）。测通了再保存，避免存一堆死代码。
- **保存即生效**：保存后立刻补采该品种报价并刷新行情表；停用（`enabled=0`）则停止采集且页面不展示；自建品种可删除（连带清掉报价与历史轨迹），内置品种只能停用不能删。
- 报价走与贵金属相同的新浪 `nf_` 内盘期货通道，K 线走东方财富。
- **只收录有公开连续报价的品种**。稀土氧化物、锑、锗、镓、钨、钼等没有稳定的免费行情源，**不伪造价格**；有代码但拿不到 K 线的品种会被列进 `skipped`，而不是塞一份编出来的曲线。
- 稀有金属与贵金属共用 `metal_quotes` 表，但品种归属记在 `metal_instruments.scope`（`rare` / `metal`），因此不会污染贵金属板块统计；报价在访问页面或 cron 时按 10 分钟新鲜度自动补采。

### 三情景模型

对每个品种取近 **60 个交易日**的日线收盘价，计算对数收益率序列：

```text
σ_d = std(ln(P_t / P_{t-1}))          # 日波动率
μ   = mean(ln(P_t / P_{t-1}))         # 日均漂移
T   = 视界交易日数（5 / 21 / 60）
悲观 = 现价 × exp(−σ_d·√T)
中性 = 现价
乐观 = 现价 × exp(+σ_d·√T)
极端区间 = 现价 × exp(±1.65·σ_d·√T)
仓位上限 = 单品种波动预算(默认 2%) ÷ 年化波动率，夹在 1%~25%
```

- **中性锚定现价，不用漂移外推**：下跌趋势里若把漂移并入中枢，「中性情景」会低于现价，容易被误读成看空目标价。动量（`μ·T`）单独输出为「近 60 日动量」，偏离超过半个区间宽度时给出「分布向悲观/乐观倾斜」的提示。
- 15.9% / 68.2% / 15.9% 是标准正态下的落区概率，**只说明区间含义，不是预测**。接口 `disclaimer` 写明「不构成投资建议」。
- 驱动因子权重（供给 / 需求 / 库存 / 成本 / 政策，合计 100）是**框架内相对重要性**，不随行情变化；每个因子都给出「当前该看什么数据」的观察点，避免用静态数字冒充实时结论。
- 结果按 `symbol|视界` 缓存 10 分钟；手动刷新行情或 POST `/api/rare/refresh` 会清空缓存。

### 财经日历批量导入

外部整理好的日历可以一次性灌进来，无需逐条录入：

```bash
curl -X POST https://<your-worker>/api/calendar/import \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"overwrite":0,"events":[
        {"date":"2026-11-06","time":"20:30","name":"美国10月非农就业","country":"美国","importance":3,"forecast":"12.5万","previous":"11.9万"},
        {"event_at":"2026-11-07 21:00","name":"美国11月密歇根大学消费者信心","importance":2}
      ]}'
```

- 时间支持 `event_at`（`YYYY-MM-DD HH:MM`）或 `date` + `time` 两种写法；单次上限 500 条。
- 去重口径为「`event_at` + `name`」：默认跳过重复项，`overwrite:1` 时覆盖并可重置提醒标记。
- 返回 `imported` / `updated` / `skipped` / `errors`，便于核对脏数据。

## 九、常见问题

> 以下说明均针对当前版本的认证、采集、行情、通知和投资工作台。

- **页面打开但 API 返回 404 / 401**：确认 `wrangler.toml` 中存在 `[assets]` 配置且已设置生产环境 `JWT_SECRET`（≥ 32 字符）。
- **改完密码后其他设备立刻掉线**：属预期行为。令牌带 `token_version`（存在 `users` 表），改密、管理员重置密码、停用账号都会递增该版本号，已签发的旧令牌随即失效，不用等 7 天自然过期。
- **连续输错密码被锁 10 分钟**：同一 IP+账号 10 分钟内失败 8 次即拒绝（计数器存 `login_attempts` 表，多实例共享）；密码输对会立即清零，管理员不会把自己锁死。
- **数据库报 `no such table`**：确认初始化的是远程数据库（`--remote`）。
- **抓取为空或报错**：上游接口可能限流或变更，稍后重试；东方财富结果需标题/正文命中关键词才会入库，可先在「数据采集 → 消息数据」增减关注关键词。
- **行情数字与行情软件不一致**：本系统使用新浪公开实时报价（沪金 / 沪银期货主连），与券商终端的延时行情、结算价口径可能存在细微差异；「昨收」为涨跌基准，期货品种实际采用昨结算基准。
- **沪金 / 沪银历史 K 线**：当前两个内置贵金属品种均支持日 K、周 K、月 K 和分时数据。
- **「数据采集」里改了间隔不生效**：间隔在**保存**后才生效，Cron 每分钟唤醒一次；5～59 秒的任务由页面访问补采。面板右上角「保存」按钮亮起并显示「保存 · N 项改动」就说明还没保存。
- **任务自己变成「已停用」了**：这是失败保护生效 —— 连续失败达到采集参数「失败」的阈值（默认 5 次）后系统会自动停用并推一条通知，避免对失效接口无限重试。到上游或参数问题修好后，把启用开关打开即可，`fail_streak` 会自动清零。
- **资讯 / 总览的统计数字比列表慢半拍**：统计聚合（总量 / 今日 / 重点 / 频道来源分布 / 趋势 / 热词）在服务端缓存 **3 分钟**（总览与资讯共用同一份），列表与行情本身实时。这是 D1 免费读额度（500 万行/天）下的刻意取舍：不缓存时，页面每 30 秒轮询一次就会反复全表扫，单开着页面一小时就能烧掉几十万行。收藏 / 删除 / 改屏蔽词会主动清缓存（同一实例内立即生效），其余情况最多等 3 分钟，或直接刷新页面。
- **改了屏蔽词要等多久生效**：入库时会把「命中屏蔽词」直接写成 `relevant = 0`。保存屏蔽词后会触发一次全量回填（`settings.news_relevance_ver` 的令牌里带屏蔽词指纹），完成后立即生效；回填是按 200 条一页跑完的，正常一两秒内结束。若想手动重跑，可删除该设置行或把 `NEWS_RELEVANCE_VERSION` 加一。
- **日志里的屏蔽词拦截**：屏蔽词使用独立的 `splitList` 解析，空值表示不拦截；如果历史配置中已有旧值，可在「数据采集 → 消息数据 → 高级设置 → 屏蔽词」中清理。
- **采集日志太多/太吵**：日志表有条数上限并按保留天数自动清理；「最近采集」面板默认展示 10 条，并提供刷新、分页和每页条数选择。需要更细的筛选或清理，可调用 `GET /api/acquire/logs` 与 `POST /api/acquire/logs/clear`。
- **快照表会不会无限增长**：不会。`metal_snapshots` 每次采集后按「快照条数（默认 2000 条）+ 快照天数（默认 90 天）」双重清理，哪个先到按哪个淘汰；两个参数都在采集页顶部「数据保留」面板可配。
- **采集日志会不会无限增长**：不会。`fetch_logs` 每次写入时自动裁剪到最近 **20000 条**（条数硬上限），并按「日志保留天数」（默认 30 天，`fetch_log_retention_days`，可在「数据保留」面板配置）删除超期记录；在此之前所有记录都留在库里，可通过 `GET /api/acquire/logs` 分页往回查。要立即瘦身，到「数据保留」面板点「立即清理日志与旧消息」或调 `POST /api/acquire/cleanup`。
- **采集日志为什么有 `manual` 记录**：数据采集页的「立即采集」与后端手动抓取接口都是真实采集，会写入 `fetch_logs`，并以 `trigger_type=manual` 标识。
- **财经日历的数据是哪来的**：目前是**自建事件库**（管理员录入 / 模板填充），不是爬外部日历。实测金十 `cdn-rili` / 金十 CDN、东方财富 `RPT_ECONOMIC_CALENDAR`、华尔街见闻日历接口都不可用或未开放（404 / 报表不存在），与其塞一份编造的日程，不如先把「录入 → 到点提醒」这条链路做通。后续若接上稳定数据源，只要往 `eco_events` 写库，前端与提醒逻辑不用改。
- **K 线指标为什么是后端算的**：前端各算一遍容易出现口径漂移（尤其是国内 SMA 平滑的 RSI/KDJ）。现在服务端用一份 K 线算出全部序列（长度与 K 线严格对齐，前期无值处为 `null`），前端只负责按 `null` 断开折线，指标数值和图表永远一致。
- **忘记跑 `schema.sql` 会怎样**：不会挂。`migrate()` 现在会自行创建全部 **21 张表**（含 `users` / `menus` / `settings`），空库首次访问即可自动初始化，`schema.sql` 只作为「显式初始化 / 建库快照」使用。注意 `migrate()` 的种子全部用 `INSERT OR IGNORE`，若先跑 `schema.sql`，则以该文件的种子为准。
- **数据源全部停用后定时任务会做什么**：`news_crawl` 会直接跳过并记录「资讯数据源全部停用」，不会白跑一轮上游请求；`metal_quote` / `metal_snapshot` 会记为失败并提示「新浪实时行情数据源已停用」；`bank_gold_quote` 的门禁独立（只看交行源 `bocom_metal` 是否启用），停用新浪行情源不影响银行金价采集。
- **编辑用户会不会把权限清空**：不会。未提交 `permissions` 时沿用该用户原有权限；改动角色时才套用该角色的默认权限。另外系统禁止把当前登录账号降权或停用，避免管理员把自己锁在系统外。
- **如何从旧版本升级**：`migrate()` 会幂等补齐当前表结构、索引、默认数据源、任务和采集参数；旧数据库可以直接升级，无需重建。**注意**：迁移现在有版本闸门 —— 库里 `settings.migrate_ver` 等于代码里的 `MIGRATE_VERSION` 时，`migrate()` 只读这一个键就返回，不再重复写种子。因此**每次改动 `migrate()` 里的建表 / 种子 / 兼容 UPDATE，必须把 `worker.js` 顶部的 `MIGRATE_VERSION` 加一**，否则改动不会对存量库生效（想强制重跑也可以手工删掉 `settings.migrate_ver` 这一行）。
- **为什么贵金属只有上海品种**：当前内置贵金属口径是沪金 / 沪银主连；稀有金属可以在品种管理中自行接入，先通过「检测」确认新浪行情和东财 K 线可用。
- **金银比是什么口径**：固定**上海口径**（沪金元/克 ÷ 沪银元/克，克价比），卡片下方标注「沪金 ÷ 沪银（克价比）」。
- **快照累计涨幅为 0**：环比与累计涨幅需要至少两次同一基准品种的采集；刚启用或切换基准时，从第一条新快照开始累计。
- **消息中心的「命中度优先」排序**：仅在有关键词时生效，按「标题命中 → 关键词标签命中 → 摘要命中」分级，同级再按时间倒序；不填关键词时等价于最新优先。
- **大屏接口在哪里**：`/api/dashboard` 是保留的后端聚合接口，当前前端没有对应页面入口。
- **稀有金属为什么只有 4 个品种**：这 4 个（碳酸锂 / 工业硅 / 沪镍 / 沪锡）是**出厂默认**，只是挑了能拿到稳定免费连续报价的战略金属期货。现在品种存库，可在「稀有金属研究 → 品种管理」里自己加（如 `AO0` 氧化铝、`CU0` 沪铜、`SS0` 不锈钢），先用「检测」验证代码能取到行情再保存。稀土氧化物、锑、锗、镓、钨、钼等只有现货报价或付费数据源，接入就等于要编价格，因此只放进「驱动因子与观察点」，不显示行情。
- **加完品种行情表没有它**：确认三件事 —— ① 品种是「启用」状态；② 行情代码前缀选对（内盘期货 `nf_`、外盘 `hf_`、上金所延期 `gds_`，且新浪对代码大小写敏感，系统会自动拼成 `nf_AO0` 这种形式）；③ 「新浪财经 · 实时行情」数据源没被停用。点「检测」能立刻看到是代码问题还是通道问题。
- **新加品种没有情景数据**：情景模型需要历史 K 线，因此必须填写有效的东财 `secid`；没有 `secid` 的品种仍可显示报价，但会被接口列入 `skipped`。
- **三情景的「中性」为什么等于现价**：中性情景刻意锚定现价，不做趋势外推；近 60 日动量单独输出。所有区间都是波动率刻度，不是价格预测。
- **仓位上限为什么这么小**：公式是「单品种波动预算 ÷ 年化波动率」。默认预算 2%、碳酸锂年化波动约 50%，算出来就是 4% 左右；想放宽可改「数据采集 → 贵金属数据 → 稀有金属单品种波动预算」。
- **材料联想是怎么算的**：内置知识库包含 39 个场景、60 种材料和 14 条材料链；查询时按场景、材料名、材料链和近 7 天真实资讯热度排序，不代表价格涨跌。
- **为什么输入「AI」第一个是铜**：算力中心的供配电母线、机柜走线和液冷管路是铜的最大增量，权重 96 高于锡（焊料）和镓（GaN 电源），所以排第一。相关度只表示「这个场景用得多不多、有没有可替代」，**不代表价格会涨**。
- **能不能自己扩充这张表**：可以。知识库就在 `worker.js` 的 `MATERIAL_TOPICS`（场景 → 材料 → 权重 → 用途）与 `MATERIAL_CATALOG`（材料分类），按同样格式加一条即可，无需改表结构；接口 `/api/rare/match` 不用动。
- **材料联想结果里的「+ 监测」做了什么**：按内置的「材料 → 行情品种」映射（`MATERIAL_SYMBOL_HINTS`，目前覆盖铜 / 铝 / 铅 / 锌 / 多晶硅 / 锰，对应沪铜、沪铝、沪铅、沪锌、多晶硅、锰硅主连）先在数据库里建品种，再立即采一次报价，加入后行情表同步出现。重复点不会重复建（返回「已在监测」）。金 / 银 / 铂 / 钯 / 镍 / 锡 / 锂 / 工业硅 本来就在监测里，直接显示「监测中」。
- **为什么有些材料只能「手动接入」**：镓、锗、铟、钽、稀土、锑、钨、钼等没有稳定的免费连续报价（现货报价或付费源），硬接就等于编价格。点「手动接入」会打开品种管理并预填材料名 / 类别 / 产业链，如果确实拿到代码（新浪 `nf_` / `hf_` / `gds_` 任一通道），填上点「检测」即可；没有就建议先不加。
- **稀有金属报价不更新**：页面与 cron 都按 10 分钟新鲜度判断，正常情况自动补采；若提示接口失败，先到「数据采集」页测一下「新浪财经 · 实时行情」的连通性（两者共用同一通道）。
- **财经日历经批量导入后重复了**：不会。去重键是「`event_at` + `name`」，`name` 差一个字就会被当作不同事件，导入前先对齐事件名即可；需要覆盖已有条目时传 `overwrite:1`。
- **热门关键词统计**：`/api/news` 仍返回 `stats.hot_keywords` 供接口调用，当前页面不展示该卡片。
- **为什么这条消息被判成利空，明明说的是涨**：判定是**按标的**做的，一条消息里可能同时有涨和跌的信号（例如「金价收复4000美元，但美元指数走强」对黄金是混合信号）。展开消息看**判定依据**（命中了哪些词）就能定位；如果确实判错了，直接在决策面板点「利多 / 利空 / 中性」人工修正，重算时不会被覆盖。
- **改完品种池 / 别名表后如何更新历史消息**：规则默认只影响新消息；对历史数据调用 `{"action":"retag"}` 或 `{"action":"resentiment"}` 重新标记和计算，人工修正过的条目会保留。
- **建仓计划里分批占比必须凑够 100% 吗**：是。占比合计必须为 100%（误差 ≤ 0.5%），否则保存会报错 —— 计划的意义就是提前说清楚每一笔买多少。价位可以填 0 表示「到价再定」，只要占比给对就行。
- **为什么银行金价表里很多涨跌是「—」**：因为官网没给全。交行 `Au99.99` 基础价不提供涨跌额；`Au*` 合约行有官方 `upDown` 涨跌额，但涨跌幅字段不可用（见下一条）。独立表这些数值列写的是**真 `null`**（不是 0、不是空串），前端统一显示 `—` 且不着色，不会用「本次采集 − 上次采集」伪造，也不会拿旧值冒充新报价。详见「银行金价（官网一手数据）」。
- **为什么交行有涨跌额却没有涨跌幅**：官网 `upDownRate` 已**确认不可用**（两次独立抓取恒为 `"-0.01%"`，与 `upDown/lastClose` 自算约 −1.7% 差约 180 倍），是错误 / 占位字段，不是待确认项。因此 `change_pct` 永久 `null`，文案写「官网涨跌幅字段不可用，未展示」；也不允许用 `upDown/lastClose` 反推，因为 T+D 行涨跌基准是昨结算价而非 `lastClose`，算术不自洽。官方 `upDown` 本身是真实值，保留。
- **为什么单位写「元/克（推断）」**：官网未明示计量单位与枚举值。按「如实标注口径」原则，一律带「（推断）」，不写成确定语气；`currency` 一律 `CNY`。当前唯一银行源（交行）按上金所惯用口径记为元/克；系统内已**不存在**「元/件」这类整件计价数据，也不做任何量纲换算。
- **银行金价和下面贵金属报价表是什么关系**：两者独立。银行表是交行官网展示的上金所行情（`Au99.99` 基础价 + `Au` 系合约，含 `Au(T+D)`），贵金属报价表是新浪行情（沪金主连 / 沪银主连），品种口径与合约不同，**不要拿同一列数字直接相减**。区块底部有固定免责说明；本系统**不做任何量纲换算**，`Ag(T+D)`（与 `metalList` 银价单位差 1000 倍）已排除在采集之外。
- **为什么银行金价有的行标「上次成功值」**：交行本次采集失败（网络超时、非 200、`TRAN_SUCCESS:"0"`、`metalList` / `metalNewList` 为空或请求报文非法）时，系统**不删除旧行、不写 0**，只把该源已有行标记为 `stale` 并在 `note` 追加「本次采集失败，显示上次成功值（采集时间 xxx）」。修复后点「刷新」即可恢复；解析出 0 条一律判失败，不会静默当正常结果。
- **为什么「采集时间」不等于「报价时间」**：`collected_at` 恒为采集时刻（北京时间），始终有值；`quote_stamp` 只放官网原文报价时间（交行 `metalList.upTime` / `metalNewList.quoteDate + quoteTime`），无则 `''` + `stamp_kind='none'` 并显示 `—`，页面列标题明确写「采集时间（非官方报价时间）」。HTTP `Last-Modified` / `Date` 不是官方报价时间，**不写入** `quote_stamp`。
